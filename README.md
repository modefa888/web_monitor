# 网页监控平台（web_monitor）

参考项目里的 `huawei_stock_monitor.py` / `check_stock_once.py` 做的网页版监控网站：
在浏览器里新建监控项、**在线编写 Python 监控代码**、设置**执行间隔**，后台按计划自动执行，
历史记录可查，状态变化时通过多渠道推送提醒。

```
启动：python3 web_monitor/app.py          # 打开 http://127.0.0.1:8787
参数：--port 9000  --host 0.0.0.0  --db /path/monitor.db

页面：
  http://127.0.0.1:8787/         公开只读看板：各服务器存量情况（无需登录）
  http://127.0.0.1:8787/mianban  管理后台（需管理员登录）
```

## 账号与权限

| 页面 / 接口 | 谁能访问 |
| --- | --- |
| `/mianban` 管理后台（新建/编辑/删除监控、通知设置、立即执行、历史） | **仅管理员**（登录后） |
| `/` 公开存量看板 + `GET /api/public/stock` | 所有人（只读，无需登录） |
| `/go/<token>` 加密跳转（解密目标地址、记录点击后 302 到活动站点） | 所有人（无需登录） |

- 首次启动自动创建默认管理员：**admin / admin123**，登录后请立即点右上角「🔑 修改密码」改掉；
- 登录会话为 Cookie（服务端签名，密钥存 `data/secret_key`），默认保留 7 天；
- 登录态按端口独立：会话 Cookie 名与绑定入口都含端口（`协议://主机:端口`），同一主机的不同端口**各自独立登录、互不影响**（如本机 8787 与 IDE 预览端口可同时各登各的），换主机 / IP / 协议需重新登录；
- 除 `login / logout / me / public/stock` 外，所有 `/api/*` 接口都要求管理员登录（未登录返回 401）；
- 公开看板只暴露名称、状态、结果消息与结果数据（data 字段），**不含监控代码、PARAMS、stdout 输出**；
- 采集结果里的跳转地址（`url` / `site_url`）**不直接下发**：公开接口只返回加密跳转链接 `/go/<token>`（HMAC 认证加密，密钥沿用 `data/secret_key`），页面源码看不到真实网址；点击时由 `/go/<token>` 解密 → 记一次点击统计 → 302 跳转（带 `Referrer-Policy: no-referrer`，不向目标站点透露来源页）；
- 采集脚本抛出的技术异常（连接失败、超时、堆栈等）**不会出现在公开看板，也不在管理端卡片/手动执行结果里刷屏**：统一替换为友好提示，完整原文只留在管理员可见的执行历史（stdout/stderr）与推送通知里；
- 公开看板数据接口有 **5 秒响应缓存 + 事件失效**：所有访客共享同一份结果，千级并发轮询不会打穿数据库；监控写入新结果时缓存立即失效，看板最多滞后一个采集周期；
- 公开看板对技术异常有**容忍窗口（基础 5 分钟 + 2 个采集间隔）**：偶尔一次采集失败继续展示上一次成功的快照（消息/数据/状态），不闪红色异常；持续失败超过窗口才对外显示。有意义的结果（如「已抢光」）不受影响，管理后台与推送通知始终立即反映真实状态；

## 功能

| 功能 | 说明 |
| --- | --- |
| 管理员登录 | 管理后台需登录才能配置采集服务；默认账号 admin / admin123（首次启动生成，务必修改） |
| 公开存量看板 | `/` 只读页面：所有人可查看各服务器（监控项）最新存量/状态，按分组展示、点击分组标题可展开/收起（记住选择），自动刷新，无需登录 |
| 404 页面 | 未知路径不再显示 Flask 默认错误页，而是展示带「星际接接乐」小游戏的 404 页（键盘/鼠标操作，30 秒一局，浏览器本地记录最高分），并提供「前往首页」入口 |
| 访客记录 | 后台「📈 访问统计」记录每次打开公开首页 `/` 的 IP、设备（含手机型号）、浏览器、操作系统与来源页；卡片展示 PV/UV/IP/移动端等指标，并提供分布与 14 天垂直柱状趋势。各模块「详情」可打开明细页，支持搜索、时间筛选、全字段展开及柱状/折线/占比多种可视化；仅统计页面打开，信息仅管理员可见 |
| 存货曲线图 | 看板卡片上的「📈 曲线」按钮弹出悬浮窗，用最近 100 次采集数据画存货变化曲线，鼠标悬停可看该时刻的剩余数量/可抢百分比与结果消息 |
| 前往站点 | 库存监控卡片上的「🔗 前往站点」按钮新标签页打开对应活动页；页面源码只有加密跳转地址 `/go/<token>`，点击时服务端解密并记录点击统计后 302 跳转；地址取自监控结果里的 `url`，可在 PARAMS 里填 `url` 覆盖默认地址 |
| 跳转统计 | 后台「🔗 跳转统计」统计「前往站点」按钮的点击：今日/累计点击量与人数、按目标地址归组的点击排行、14 天趋势与最近点击明细（IP / 设备 / 浏览器）；记录保留 90 天，仅管理员可见 |
| 接口统计 | 后台「🔌 接口统计」统计所有 `/api/*` 调用：每个接口的今日/累计次数、错误数、平均与最大耗时、最近调用时间，附 14 天调用/错误趋势与最近 50 条明细（方法/状态码/耗时/IP）；支持「全部 / 🌐 公共接口 / 🔐 需登录」切换（登录、登出、会话与 `/api/public/*` 算公共接口，其余需登录）；路由按模板归一（如 `/api/monitors/<id>`），未登录 401 与未知路径 404 也纳入统计；记录保留 30 天，仅管理员可见 |
| 接口启停管理 | 「🔌 接口统计」里点击任意接口行弹出管理面板，可一键 ⛔ 停用 / ✅ 启用该接口：停用后调用立即返回 503（仍计入统计），可随时恢复；停用列表持久化在设置里、不被设置保存覆盖；登录 / 登出 / 会话 / 接口管理 / 接口统计为受保护接口，不可停用，避免把自己锁在外面；停用公开看板数据接口时，看板会展示居中的「🚧 看板数据接口已停用」占位卡片，接口恢复后自动重新加载 |
| 监控项分组 | 编辑监控时填「分组」即可归类；分组栏末尾的 `＋` 可单独创建空分组（保存在设置里，删光监控后仍保留）；首页按分组折叠展示 + 筛选，公开看板同样支持 |
| 在线编写监控代码 | 编辑器里写 Python，支持套用模板：HTTP 探测 / 华为云活动库存 / 阿里云限时抢购库存 / 阿里云新人专享轻量服务器 / 腾讯云活动商品库存 / 京东云秒杀库存 / TCP 端口探测 / 运行本地 Python 脚本 / 空白 |
| 黑白主题切换 | 页面右上角「☀️/🌙」按钮切换深浅色，选择保存在浏览器本地 |
| 执行间隔 | 每个监控项独立设置（最小 3 秒），另有单次超时限制，超时自动终止 |
| 定时监控时段 | 可设多个时段（北京时间 `HH:MM-HH:MM`，逗号分隔，如 `10:00-12:00, 15:00-17:00`），只在时段内自动执行，其余时间不监控；支持跨零点，留空=全天 |
| 商品附加信息 | 每个监控项可设置厂商名（如腾讯云）、地区（如上海/北京）、价格类型（新用户首年价 / 老用户续费价 / 常规价）、限购数量（0=不限）与是否需实名，在后台卡片和公开看板上展示 |
| 失败自动重试 | 每个监控项可设重试次数与间隔（0=不重试）；仅定时任务生效，手动执行保持立即反馈；历史记录真实尝试次数 |
| 慢执行告警 | 设「慢执行阈值（毫秒）」后，耗时超限会在消息里标注 ⚠ 并在卡片上显示「慢」徽标；快慢翻转时按推送策略提醒 |
| 历史趋势图 | 执行历史弹窗顶部纯 SVG 柱状趋势图（左旧右新）：绿色=成功、红色=失败、黄框=慢执行，悬停看详情 |
| 后台调度 | 独立线程轮询调度，到期的任务并行执行（线程池，最多 8 个并行） |
| 立即执行 / 测试运行 | 「立即执行」落库计一次历史；编辑器里的「测试运行」直接跑当前编辑内容，不落库 |
| 执行历史 | 每个监控项保留最近 200 条：结果、耗时、消息、完整 stdout/stderr、触发方式（定时/手动） |
| 状态看板 | 正常/异常/暂停统计、最近与下次运行时间、成功率、平均耗时、连续失败计数 |
| 多渠道推送 | 与旧脚本同款：企业微信 / 钉钉 / Server酱 / Bark / Telegram / 通用 Webhook / console |
| 推送策略 | 每个监控项可选：状态变化时推送 / **有库存时推送（无货不推）** / 仅失败时推送 / 不推送；「有库存时推送」只在无货→有货时提醒一次，有货期间的刷新和数量变化不打扰；「状态变化」包含有货↔无货、剩余数量变化、慢执行翻转；全局推送冷却时间 |

## 监控代码约定

每次执行时，平台把你的代码写进临时脚本，在**独立 python 子进程**里运行。代码里可用：

```python
# PARAMS：监控项里配置的 JSON 参数（字典），例如 {"url": "...", "keyword": "..."}
# emit(ok, message, data=None)：上报本次结果
#   ok      是否正常（True/False）
#   message 一句话结果（显示在卡片与推送里）
#   data    任意可 JSON 化的附加数据（历史详情里可看）

import requests
resp = requests.get(PARAMS["url"], timeout=10)
emit(resp.status_code == 200, f"HTTP {resp.status_code}", {"len": len(resp.content)})
```

结束方式（任选其一，推荐 `emit`）：

1. 调用 `emit(True, "一切正常")` —— 以 `__RESULT__` 行上报，最精确；
2. 不调用 `emit`：退出码 0 = 成功（message 取 stdout 末行），非 0 = 失败（兼容旧式“末行输出单行 JSON”的脚本，如 `check_stock_once.py`）。

执行超时、代码抛异常、非零退出码都会记为一次失败，不会影响平台本身。

## 推送渠道配置

页面右上角「⚙ 通知设置」里可视化编辑：每个渠道一个 Tab（控制台 / 邮箱 / 企业微信 / 钉钉 /
Server酱 / Bark / Telegram / Webhook），表单填字段、可启用停用、可加多个同类渠道、
每个渠道有独立「测试此渠道」按钮。同一类型的渠道可以添加多个，改动点「保存」才生效。
底层格式与 `monitor_config.json` 里的 `notify.channels` 完全一致，可原样迁移：

```json
[
  { "type": "console" },
  { "type": "email",      "smtp_host": "smtp.qq.com", "smtp_port": 465,
    "user": "你的QQ号@qq.com", "password": "SMTP授权码", "to": ["接收邮箱@example.com"] },
  { "type": "wecom",      "webhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx" },
  { "type": "dingtalk",   "access_token": "xxx", "secret": "SECxxx（加签可留空）" },
  { "type": "serverchan", "sendkey": "SCTxxx" },
  { "type": "bark",       "url": "https://api.day.app/你的Key" },
  { "type": "telegram",   "bot_token": "123:abc", "chat_id": "xxx",
    "proxy": "http://127.0.0.1:7890（国内直连不通才填）" },
  { "type": "webhook",    "url": "https://你的服务/notify" }
]
```

渠道要点：

- **email**：QQ/163 邮箱的 `password` 填「SMTP 授权码」（邮箱设置→账户里开启 SMTP 后生成），不是登录密码；
  端口 465 走 SSL（默认），587 走 STARTTLS（需 `"use_ssl": false`）；`to` 可填多个收件人。
- **telegram**：`bot_token` 找 @BotFather 创建机器人获取；`chat_id` 可给 bot 发条消息后访问
  `https://api.telegram.org/bot<token>/getUpdates` 查看。国内直连不通时填 `proxy`
  （http 代理直接可用，`socks5://` 需先 `pip install pysocks`）。

保存前可点「发送测试推送」验证。`console` 渠道会把消息打印到服务端日志（`web_monitor/data/server.log`）。

## 目录结构

```
web_monitor/
├── app.py             # Flask 后端 + API + 管理员鉴权 + 启动入口
├── sitelink.py        # 「前往站点」加密跳转 token（HMAC 认证加密，纯标准库）
├── store.py           # SQLite 存储（监控项 / 执行历史 / 设置 / 管理员账号 / 访问与点击记录）
├── scheduler.py       # 子进程执行器 + 后台调度线程
├── notifier.py        # 多渠道推送（与旧脚本同款实现）
├── code_templates.py  # 内置监控代码模板
├── static/index.html  # 管理后台单页（原生 JS，无构建依赖）
├── static/stock.html  # 公开只读存量看板（无需登录）
├── static/404.html    # 带小游戏的自定义 404 页面（复用站点 favicon.svg 图标）
└── data/              # 运行时生成：monitor.db、secret_key、server.log、server.pid
```

## 常用操作

```bash
# 启动（前台运行）
python3 web_monitor/app.py

# 供局域网访问（管理页需登录；公开看板只读。监控代码等同于任意代码执行，请勿暴露公网）
python3 web_monitor/app.py --host 0.0.0.0 --port 8787

# 停止后台服务
kill $(cat web_monitor/data/server.pid)    # 或 pkill -f web_monitor/app.py

# 数据备份 / 迁移：直接拷贝数据库文件即可
cp web_monitor/data/monitor.db ~/backup/monitor.db.$(date +%F)
```

## 从旧脚本迁移

- 旧的 `monitor_config.json` 里 `notify.channels` 可原样粘贴到「通知设置」；
- `check_stock_once.py` 这类"末行输出单行 JSON"的脚本：新建监控时套用「运行本地 Python 脚本」模板，
  在 PARAMS 里填脚本绝对路径即可直接执行，不用改一行代码；也可以把脚本代码整段贴进监控代码框；
- 华为云库存监控：新建监控 → 套用「华为云活动库存」模板 → 在 PARAMS 里改 `promotion_id` 即可，
  推送策略选「状态变化时推送」就是抢到货提醒。

## 安全提示

- 管理后台需要登录（默认 admin / admin123，请第一时间修改），且监控代码等同于在本机执行任意 Python；
- 默认只监听 `127.0.0.1`；监控代码在独立子进程运行、有超时保护，但**没有沙箱隔离**，请只运行自己写的代码；
- 公开看板 `/` 无需登录，只读展示各监控项的存量/状态摘要；访问统计会保存访客 IP 与 User-Agent 用于追溯（仅管理员可见，公开接口不返回）；
- 需要外网可访问时，建议放在内网或反代后，并为 `/` 与 `/api/*` 追加更严格的访问控制。
